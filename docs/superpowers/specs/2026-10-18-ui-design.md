## 1. Purpose

This module covers everything the player and operator read or point at:

- the attract screen;
- mode selection with the hand cursor;
- calibration prompts;
- the in-game HUD and scorecards;
- the pause overlay;
- results;
- the keyboard-only operator panel.

It must be readable from 3 m away (GC-8), usable with an arm instead of a mouse (GC-7), flat (SOT-1), and built from components (SOT-2).

**Implements:** `IUiCues`.

**Consumes (wired by App):**

- `IGameEvents`, `IGameCommands`
- `IHandCursor`
- `IPlayerCalibrator`
- `IThrowSource` (phase, throws and rejections: swing prompts, `ThrowStats`, toasts)
- `IPlayerInput` (status, and the latest pose for the skeleton overlay)
- `ICameraPreview`
- `ILeaderboardStore` (read only)
- `IRecordingIndicator`
- `IOperatorActions`
- `ITrackingDiagnostics`

## 2. Technology and structure

**Technology:** UI Toolkit (runtime). UXML for structure, USS for style, C# controllers. The text font is **Inter** (SIL Open Font License), imported as a UI Toolkit font asset. Inter is Claude's call; it's open-licensed and very legible at distance.

```
Modules/UI/Runtime/
├─ Styles/
│  ├─ Tokens.uss                 the ONLY file with color literals (M-8); all design tokens as USS variables
│  └─ Base.uss                   resets + typography utility classes (.text-prompt, .text-title, .text-body, .text-caption)
├─ Components/<Name>/            <Name>.uxml + <Name>.uss + <Name>.cs  (section 4)
├─ Screens/<Name>Screen/ and Screens/<Name>Overlay/   <Name>.uxml + .uss + .cs — compose components; layout only, no colors
├─ Core/
│  ├─ ScreenRouter.cs            GameState + TrackingStatus → visible screen/overlays (section 5)
│  ├─ DwellTracker.cs            pure dwell timing logic (section 6)
│  ├─ CursorHitTester.cs         maps IHandCursor.Position → VisualElement under cursor (panel.Pick)
│  ├─ MarkFormatter.cs           RollMark → "X", "/", "–", "7"
│  ├─ SpeedFormatter.cs          m/s → "29 km/h · 18 mph"
│  └─ UiCueHub.cs                implements IUiCues
├─ Root/UiRoot.cs                the module's only MonoBehaviour; owns the UIDocuments; Initialize(...) entry point for App
└─ Config/
   ├─ UiTuning.cs                dwell time, toast duration, transition times
   └─ UiStrings.cs               ScriptableObject holding every user-facing string (one place for copy + future localization)
```

## 3. Design tokens (`Tokens.uss`), all flat (SOT-1)

```css
:root {
  /* surfaces */   --color-surface-0: #14161F; --color-surface-1: #1E2130; --color-surface-2: #2A2E42;
  /* text */       --color-text-primary: #F5F3EE; --color-text-secondary: #A7ABBE; --color-text-on-accent: #0B0D14;
  /* roles */      --color-accent: #3CE7FF; --color-success: #37D67A; --color-warning: #F2C14E; --color-danger: #FF4D6D;
  /* players */    --color-player-1: #2E86DE; --color-player-2: #E4572E; --color-player-3: #17BEBB; --color-player-4: #B97CF3;
  /* focus */      --color-focus: #FFFFFF;
  /* spacing */    --space-1: 8px; --space-2: 16px; --space-3: 24px; --space-4: 32px; --space-5: 48px; --space-6: 64px; --space-7: 96px;
  /* radius */     --radius-1: 8px; --radius-2: 16px; --radius-pill: 999px;
  /* borders */    --border-1: 2px; --border-2: 4px;
  /* type */       --font-prompt: 64px; --font-title: 48px; --font-score: 40px; --font-body: 36px; --font-caption: 28px;
  /* motion */     --motion-fade: 200ms; --motion-color: 120ms; --motion-pop: 200ms;
}
```

**Rules:**

- Components reference only `var(--…)`.
- Captions (28 px) are only for secondary labels that aren't required for play, such as "Frame" headers. Everything a player must read is 36 px or larger (GC-8).
- The player colors match presentation's `Palette` asset.
- Changing a token value is fine. Adding a gradient, shadow or blur isn't (SOT-1).
- **Contrast:** every text/background pair the components use is listed in `Tokens.contrast.json`, and a unit test parses `Tokens.uss` to check each pair is at least 4.5:1 (WCAG AA).

**Motion:** only time-based changes are allowed. At every instant each element is still flat:

- screen fades: opacity, `--motion-fade` (200 ms);
- color transitions: `--motion-color` (120 ms);
- transform animations, such as scale pops and slides: `--motion-pop` (200 ms);
- progress-ring sweeps.

No blur, no drop shadows, no glow.

The motion durations are tokens in `Tokens.uss`. If USS doesn't accept `var()` inside `transition-duration`, the builder sets those durations from `UiTuning` in C# instead, and records which approach was used in the plan.

## 4. Components

Each row is one folder in `Components/` (SOT-2, M-8).

| Component | Responsibility | Key states / API |
|---|---|---|
| `DwellButton` | A large target (240×120 px or more) with a label and optional icon. Its progress ring fills while the cursor hovers. | idle / dwelling(progress) / confirmed (150 ms flash) / disabled / selected. `event Confirmed`. Uses `DwellTracker`. |
| `ProgressRing` | An arc drawn with `Painter2D`: a flat stroke on a flat track | `Progress` 0..1, `Thickness`, color class |
| `HandCursor` | Ring and dot at `IHandCursor.Position`; hidden while inactive | Moves through `style.translate` only (no layout cost) |
| `PromptBanner` | One big prompt line plus an optional sub-line | `SetPrompt(stringKey)` |
| `FrameCell` | One frame: up to 3 mark boxes plus the cumulative score | current-frame highlight = accent border (flat) |
| `ScoreCardView` | `PlayerBadge` plus N `FrameCell`s plus the total | compact / expanded |
| `PlayerBadge` | A flat color chip plus "Player N" | color from `--color-player-<n>` |
| `CameraPreview` | Mirrored preview texture (scale x −1), skeleton overlay (Painter2D lines, flat accent, 4 px; joints as flat circles), play-zone guide (flat outline) | `tracked` / `searching` |
| `ThrowStats` | After each throw (`IThrowSource.Thrown`): speed (`SpeedFormatter`) and a hook label: "Straight" (\|hook\| < 0.1), "Light hook" (0.1 ≤ \|hook\| < 0.4), "Big hook" (≥ 0.4). Thresholds are `UiTuning` fields. | Visible for 3 s; pop-in = scale 0.9 → 1.0 + opacity fade, 200 ms |
| `Toast` | A short message, e.g. a rejection reason | auto-hides after `toastDuration` (2.5 s) |
| `Countdown` | `ProgressRing` plus the seconds remaining | — |
| `LeaderboardTable` | Rank, name, score; "You" highlight for the current game's entries | Today / All time |
| `TrackingStatusPanel` | Operator-facing message for each `TrackingStatus` error, with fix steps | — |
| `RecordingBadge` | A flat red "Recording" pill, shown when `IRecordingIndicator.IsRecording` | — |
| `OptionGroup` | A row of `DwellButton`s where exactly one is selected (players, frames, difficulty) | `SelectedIndex` |

**Operator panel** (`OperatorPanel`):

- Keyboard only. Platform owns the shortcut and toggles it through App.
- UI Toolkit focus navigation: arrow keys and Enter; Esc closes.
- **Contents:**
  - camera list (`ITrackingDiagnostics.Cameras`);
  - default difficulty;
  - master volume;
  - pose-recording toggle;
  - "Reset leaderboard", which asks for confirmation;
  - live tracking stats (fps, p50/p95 latency, drops), plus a warning when camera video effects are on;
  - "Quit".
- Changes go through `IOperatorActions.ApplySettings`.

## 6. Hand interaction (`DwellTracker`, `CursorHitTester`)

- **Hit testing:** `CursorHitTester` converts `IHandCursor.Position` (0..1) into panel coordinates and picks the topmost `DwellButton` under it.
- **Dwell:**
  - `DwellTracker.Update(isInside, dt)` advances progress by `dt / dwellTime`, where `dwellTime` is 1.2 s.
  - Leaving the button for longer than `dwellGrace` (0.15 s) resets the progress.
  - Reaching 1.0 fires `Confirmed` once.
  - The button then locks for `dwellCooldown` (0.6 s), so one hover can't confirm twice.
- **Cues:** while dwelling, `UiCue.DwellTick` fires at 25%, 50% and 75% progress; `UiCue.Confirm` fires on confirm; `UiCue.Toast` fires when a toast appears.
- **Inactive cursor:** dwelling is impossible and the cursor is hidden. Prompts tell the player to "Raise your hand to choose".

## 8. Acceptance criteria

1. All tests pass, and the SOT-1 and SOT-2 validators pass.
2. **Readability check:** on the booth TV, a reviewer standing at 3 m can read every prompt and score. This is recorded with a photo in the plan's verification step.
3. UI update cost is 1 ms or less per frame (Profiler marker `UI.Update`), with zero GC allocations per frame in AwaitThrow.
4. A first-time user picks a mode with the hand cursor in 10 s or less, in 4 of 5 hallway tests.

## 9. Decisions made here (Claude's calls, please check)

- **Dwell-to-select (1.2 s)** instead of gestures like push or grab. It's the most reliable choice for first-time walk-up users.
- **The Inter font.**
- **Speed is shown in both km/h and mph.**
- **The operator panel is keyboard only.** Players can never reach it.
