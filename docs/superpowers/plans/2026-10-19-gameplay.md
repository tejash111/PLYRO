# Gameplay and Scoring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `Bowling.Gameplay`: ten-pin scoring for 3, 5 or 10 frames, the session state machine from Attract to Results, and the `IGameEvents`/`IGameCommands` facade. Everything is tested in EditMode against the `Bowling.Testing` fakes.

**Architecture:**

- Plain C# logic lives in `Runtime/Core/`. A thin `GameplayDriver` MonoBehaviour calls `GameplayService.Tick()`.
- The pure pieces come first: `ScoreCard`, `FrameRules`, `GameSession` and `SnapshotBuilder`.
- `GameStateMachine` then drives them from `IClock` time and the dependency events.
- `GamePublisher` raises the game events in the R22 order, and isolates each subscriber.
- `GameplayService` is the public facade. It runs every entry point to completion, so a command issued from inside an event handler waits its turn.

**Tech Stack:** Unity 6000.3.26f1, C# (.NET Standard 2.1), Unity Test Framework 1.6.0 (NUnit, EditMode), `Bowling.Testing` fakes.

**Spec:** `docs/superpowers/specs/2026-10-18-gameplay-design.md`. Read it together with:

- system design §6.5–6.6 (`docs/superpowers/specs/2026-10-18-motion-bowling-system-design.md`), which defines the contracts;
- the "Execution notes" of `docs/superpowers/plans/2026-10-18-project-foundation.md` (rulings R21, R22 and R26, and the hand-off notes).

## Global Constraints

- **SOT-1:** at any single rendered frame, every authored surface or element is filled with exactly one flat color. No color may be defined as an interpolation between two or more colors across space. Gameplay authors no visuals, but G-2 still scans its `.cs` files.
- **SOT-2:** every runtime module references only `Bowling.Contracts`. `Bowling.App` is the single composition root. One public type per file, and the file name matches the type name. Soft limit 300 lines, hard limit 400.
- **GC-1:** Unity 6 LTS: URP, Metal only, IL2CPP, target macOS Apple Silicon (arm64). The exact editor version is pinned in `ProjectVersion.txt`.
- **GC-2:** minimum macOS 14.0, Apple M1 or newer.
- **GC-3:** fully offline at runtime. No network calls.
- **GC-4:** camera images never leave process memory. Only landmark data may be recorded, and only when the operator turns recording on.
- **GC-5:** SI units. Lane frame: origin at the center of the foul line, +Z down the lane, +X to the bowler's right, +Y up.
- **GC-6:** physics fixed step 1/240 s. Render target 60 fps (vsync). Tracking target 30 fps or more (60 if the camera allows).
- **GC-7:** players need no mouse, keyboard or touch. The keyboard is for the operator only.
- **GC-8:** the UI is readable at 3 m: prompt text 64 px or larger, body text 36 px or larger, at 1080p reference resolution.
- **Frame budget** (system design §8): PoseInput, ThrowDetection and Gameplay together take 1 ms or less per frame.
- **Contracts are fixed.** Gameplay implements `IGameEvents` and `IGameCommands`, and consumes the other interfaces exactly as system design §6 defines them. It changes no Contracts type.
- **Assemblies:**
  - `Bowling.Gameplay` references `Bowling.Contracts` only.
  - Its tests (`Bowling.Gameplay.Tests.EditMode`) also reference `Bowling.Testing`.
  - `AssemblyInfo.cs` already grants `InternalsVisibleTo` to the test assemblies.
- **Events (R21, R22):**
  - Every transition assigns `Current` first, then raises `StateChanged`, then `SnapshotChanged`.
  - A scored roll raises `StateChanged(Scoring)`, then `RollScored`, then `SnapshotChanged`, with `Current` already the new snapshot.
  - Published snapshots are never mutated.
- **Attract guard:** Attract calls `throwSource.Disarm()`. Only if `!sim.IsRolling` does it then call `sim.SetBumpers(false)` and `sim.SetRack(PinMask.All)`, because both throw while a roll is in progress.
- **Clocks:** game timers use `IClock.Now` only. `ThrowEvent.Timestamp` (camera clock) is passed to `sim.Roll` untouched and never compared with `IClock`.
- **Tuning:** every duration, preset and default-profile value is a `GameplayTuning` field. Assist and bumpers live in `DifficultyCatalog`. No literal durations or rule numbers in `Core/`; the rules of bowling (10 pins, 3 balls in the final frame) are not tuning.
- **C#:**
  - Namespaces: `Bowling.Gameplay` (runtime) and `Bowling.Gameplay.Tests`. Subfolders add no namespace segment.
  - `PascalCase` for types and members, `_camelCase` for private fields.
  - Public types: `GameplayService`, `GameplayDriver`, `GameplayTuning`, `DifficultyCatalog`. Every other Gameplay type is `internal`, still one type per file.
- **No statics:** no static mutable state, no singletons, and no `FindObjectOfType`, `GameObject.Find` or `Resources.Load`. Static pure functions (`FrameRules`, `SnapshotBuilder`, `DefaultProfiles`) are fine.
- **Tests:**
  - EditMode only. Use `Assert`, never `Assume` (R26).
  - Run them with `tools/ci/run_unity_tests.sh`, never the Unity binary.
  - Before every commit, `bash tools/ci/verify.sh` prints `VERIFY OK`.
- **Commits:** every commit made by an AI agent ends with its `Co-Authored-By:` trailer.

## Review Focus

1. **Presence that flickers, or a player who walks off mid-roll.** Only continuous absence counts, and it carries across states. A player who leaves during Rolling is paused at the first Tick of the next state, and abandoned 15 s after the pause began. The roll still scores. Tests: Task 13, `FlickerDoesNotAddUp` and `LeavingDuringTheRollPausesAtTheNextState`.
2. **Calibration with nobody there.** This covers entering Calibrate with the zone empty (every multiplayer turn change) and a player stepping out mid-gesture (`Failed(PlayerLeft)`). The next person to step in still gets a real calibration; only `Failed(Timeout)` counts toward the default profile. Tests: Task 10, `PlayerLeftIsNotAFailure` and `CalibrateWithNobodyPresentWaitsToBegin`; Task 13, `TurnChangeWaitsThirtySeconds`.
3. **A gutter, then all ten.** `0, 10` is a Spare (10 plus the next roll), not a Strike. The same holds in the final frame (`X, 0, 10` and `0, 10, 10`), and the racks agree with the marks. Tests: Task 3, `GutterThenTenIsASpare`, `FinalFrameStrikeGutterTen` and `FinalFrameGutterTenTen`; Task 4, the table rows and `FrameRulesAgreementTests`.
4. **The operator pauses at an awkward moment** (Rolling, Scoring, AwaitThrow or GameOver). The roll still scores, and the throw source is re-armed on resume. An operator pause with the player present waits for `Resume()`. The leaderboard gets exactly one entry per player. Tests: Task 13, `OperatorCommandTests`.
5. **Commands at the wrong time, or from inside an event handler** (a dwell button firing twice, or a UI handler calling `SelectMode` from `StateChanged`). They are ignored or queued. Every transition still raises its full event sequence in R22 order, and `Current` is current in every handler. Tests: Task 9, `RunToCompletionTests` and `SelectModeOutsideModeSelectIsIgnored`; Task 13, the ignored-command tests.

## Spec refinements (approved with this plan; Task 1 writes them into the spec)

Writing the plan surfaced one error and several open points in the gameplay spec. Each line is a decision the tasks below rely on.

- **P-1 (error in §5):** an N-frame perfect game is N + 2 strikes.
  - 3-frame perfect is **5 × 10** (90), not 6 × 10. 5-frame perfect is **7 × 10** (150), not 8 × 10.
  - With the spec's counts, the extra roll would end in `InvalidOperationException`.
- **P-2 (marks):** a rack is *fresh* at ball 1, and after a final-frame reset (a strike or spare).
  - **Strike:** 10 pins on a fresh rack.
  - **Spare:** clears every standing pin on a rack that isn't fresh. So `0, 10` is a Spare, and the final frame `X, 0, 10` reads Strike, Miss, Spare.
  - **Miss:** 0 pins. **Count:** anything else.
  - `FrameRules` takes freshness as an input, because a mask can't tell a fresh rack from one where ball 1 hit nothing.
- **P-3 (absence and timers):**
  - "Presence false for X" means continuous absence of at least X. It is measured from the moment presence last became false (`PresenceChanged`, with a poll each Tick as a backstop), and it carries across state changes. Presence returning resets it.
  - Results counts its absence from the later of Results entry and the start of the absence, as Paused does (P-5).
  - Every timer fires on the first Tick at which the elapsed time is at least its duration.
  - At most one timer-driven transition happens per Tick.
- **P-4 (Calibrate):**
  - `Begin()` runs on entry only if the player is present.
  - Any Tick in Calibrate with the player present and no calibration running calls `Begin()`. That covers entering while absent, and the end of a `Failed(PlayerLeft)` or `Failed(TrackingLost)`.
  - Only `Failed(Timeout)` counts toward the two-failure fallback. The count resets on every Calibrate entry, including a resume.
  - A *turn-change* Calibrate uses `turnChangeWait` as its pause threshold. That is a new turn in a game of 2 or more players, not the first turn.
- **P-5 (Paused):**
  - On enter, Paused also calls `calibrator.Cancel()`.
  - The resume state is the state it paused from, except that AwaitThrow resumes as AwaitReady, which re-arms.
  - It resumes when the player is present after having been absent at some point during this pause, or on `Resume()`.
  - It abandons to Attract after `abandonAfterPause` of absence, counted from the later of the pause entry and the start of the absence. So an operator pause with the player present lasts until `Resume()`.
- **P-6 (operator commands):**
  - `Pause()` in Rolling or Scoring is deferred to the first Tick after the next state is entered. A pause that begins (from the presence rule or a direct `Pause()`) satisfies a pending deferred `Pause()`, so it is not applied again.
  - Resuming into GameOver doesn't submit again: there is one submission per game.
  - Attract on enter also calls `calibrator.Cancel()`.
  - A command where it doesn't apply is ignored and logged `Info("Gameplay", "<Command> ignored in <State>")`: `SelectMode` outside ModeSelect and Results, `Pause` in Attract, Results or Paused, `Resume` outside Paused, and `Abandon` in Attract.
  - `SelectMode` validates first, in any state: players 1–4, frames 3, 5 or 10, and a defined `Difficulty`. Anything else throws `ArgumentOutOfRangeException`.
  - "Play again" is `SelectMode` in Results with whatever arguments the UI passes.
- **P-7 (run to completion):**
  - `Tick`, the four commands and every dependency event handler run to completion.
  - A call that arrives while another is running is queued, and runs after it in call order. Examples: a subscriber calling `Abandon()` from `StateChanged`, or a dependency raising an event from inside a Gameplay call.
  - So every transition raises its full event sequence before the next one begins.
- **P-8 (subscriber isolation):** each subscriber of each event is invoked on its own. One that throws is logged as `Error("Gameplay", "<EventName> subscriber failed", exception)`, and the others still run.
- **P-9 (scoring against the rack):**
  - The pin count is `(rack & ~StandingAfter).Count()`, and the next rack comes from `rack & StandingAfter`.
  - A `StandingBefore` that differs from the rack is logged as a warning.
  - `RollOutcome.Result` is the simulator's result, unchanged.
- **P-10 (unexpected inputs):**
  - `Thrown` is also accepted in AwaitReady (the source passed Ready within one frame).
  - `Rejected` in AwaitReady is ignored, because the source is already waiting.
  - These are ignored and logged `Warn("Gameplay", "<Event> ignored in <State>")`: `Thrown` or `Rejected` anywhere else, `RollCompleted` outside Rolling, and `CalibrationCompleted` or `CalibrationFailed` outside Calibrate.
- **P-11 (snapshots):**
  - During Scoring, `CurrentPlayer`, `CurrentFrame` and `CurrentBall` name the roll just scored. They move on when Scoring ends.
  - *Lobby* snapshots have no players, `CurrentPlayer` 0, `CurrentFrame` 1 and `CurrentBall` 1, with `FrameCount = PresetFrameCount` and `Difficulty` set to the preset difficulty. They are Attract, Join, ModeSelect, and Paused when paused from Join or ModeSelect.
  - The preset difficulty is read from settings at construction and on each ModeSelect entry.
  - Attract drops the session.
  - The constructor enters Attract: it runs Attract's on-enter actions and assigns `Current`, but raises no events.
- **P-12 (leaderboard):**
  - All entries of one game share one `PlayedAtUtc`, from an injected `Func<DateTime> utcNow`.
  - A `Submit` that throws is logged as an Error. The other entries are still submitted, and the game still reaches Results.
- **P-13 (tuning):**
  - New `GameplayTuning` fields: `ResultsAbsent` 3.0 s (the Results row's "3 s"), `PresetPlayerCount` 1 and `PresetFrameCount` 3.
  - The default profile `DefaultProfiles.For(tuning)` uses: Right hand, `ArmLengthM` 0.60, `ShoulderWidthM` 0.38, `NeutralImageX` 0.5.
  - The assets live at `Assets/_Project/Config/Gameplay/GameplayTuning.asset` and `DifficultyCatalog.asset`.
- **P-14 (components, §2):** eleven more `Core/` types: `RackDecision`, `PresenceTracker`, `PauseTracker`, `GamePublisher`, `LeaderboardWriter`, `CalibrationRun`, `StateEntryActions`, `LobbyFlow`, `GameEndFlow`, `TurnFlow` and `PauseFlow`.

### Task 3: ScoreCard

**Files:**

**Interfaces:**

  ```csharp
  internal sealed class ScoreCard
  {
      public ScoreCard(int frameCount);              // 3, 5 or 10; otherwise ArgumentOutOfRangeException
      public int FrameCount { get; }
      public bool IsComplete { get; }
      public int CurrentFrame { get; }               // 1-based frame of the next roll; unchanged once complete
      public int CurrentBall { get; }                // 1..3, ball of the next roll; unchanged once complete
      public int PinsStanding { get; }               // pins standing for the next roll; 0 once complete
  ```
